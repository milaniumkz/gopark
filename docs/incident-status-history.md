# История статусов инцидентов

В карточках приложения бригадира (общий список и карточка водителя) отображаются дата и время каждого изменения статуса и этапа: ожидание ремонта, ремонт, завершение, закрытие, запрос/подтверждение списания, осмотр и штрафстоянка. История остаётся в архиве; повторный переход в тот же этап после другого этапа сохраняется отдельной записью.

API возвращает `statusHistory`: массив `{ status, serviceStage, changedAt }`. Даты сохраняются сервером, отображаются в часовом поясе устройства. Изменение заметки без изменения статуса/этапа не добавляет запись.

## Обновление базы

Перед запуском новой версии API применить совместимую SQL-миграцию `apps/api/prisma/migrations/20261006060000_incident_status_history/migration.sql` и заново сгенерировать Prisma Client. Миграция добавляет JSONB-колонку и триггер, который атомарно дописывает переходы, включая изменения из CRM. Она не изменяет существующие статусы и не удаляет данные. На рабочей базе выполнять только через обычный процесс обновления с резервной копией.

В репозитории отсутствует исходная цепочка Prisma-миграций: для существующей базы с историей миграций необходимо согласовать новую миграцию с этой историей; для базы без `_prisma_migrations` сначала требуется корректный baseline или применение SQL через принятый процесс миграций. Эта миграция не создаёт остальные таблицы для пустой базы.

Старые переходы восстановить невозможно: у старых инцидентов история первоначально пуста. Карточка сообщает «История смены статусов не записана», сохраняя известную дату события. После следующего изменения появляется новая датированная запись; неизвестные прошлые даты не подставляются.

## Проверки

`corepack pnpm --filter @gopark/api exec node --loader ts-node/esm --test src/common/repositories/incident-history.test.ts`

Проверяются повторные переходы, сохранение предыдущих дат, отсутствие дублей и отсутствие выдуманных дат у старых записей. На изолированной PostgreSQL 16 проверены SQL-миграция и триггер. Через HTTP проверены создание инцидента, четыре перехода, закрытие и выдача одинаковой истории в списке и карточке водителя.
